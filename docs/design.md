# JNU OSS Platform Mock Design Notes

## Product Shape

이 시연 화면은 랜딩 페이지가 아니라 challenge/competition portal이다. 첫 화면은 `/login`이며, 사용자는 외부인, 학생, 교직원, 시스템 관리자 persona를 선택해 각자의 업무 화면으로 들어간다. 중심 객체는 대회이고, 대회 상세에서 신청, 팀, GitHub 저장소, 리더보드, 자료가 탭으로 연결된다.

## Layout Rules

- 대회 목록은 DACON/Kaggle형 카드 그리드로 제공하고, 상태 필터와 검색/정렬은 URL query로 표현한다.
- 상세 화면은 `개요`, `신청/팀`, `저장소`, `리더보드`, `자료` 탭으로 나누어 한 화면에 서로 다른 목적의 카드를 섞지 않는다.
- 공개 화면은 개인정보를 제거한 공개 대회, 공개 저장소, 활동 리더보드만 보여준다.
- 학생 화면은 신청 이력과 저장소 배정 상태를 먼저 보여주고, 교직원 화면은 검토 큐와 신청 집계를 먼저 보여준다.
- 시스템 관리자 화면은 사용자 상태와 GitHub API 호출 이상치를 분리해서 보여준다.

## Visual Rules

- 전남대학교 소프트웨어중심대학사업단의 기관형 톤을 따른다. 기본 색은 green/teal 계열을 사용하되, 배경은 밝고 표/카드 중심의 업무 화면으로 유지한다.
- hero형 마케팅 섹션은 사용하지 않는다.
- 카드 안에 또 다른 장식 카드를 넣지 않는다. 목록 내부 항목은 행이나 얇은 구분선 중심으로 처리한다.
- 한국어를 기본 UI 언어로 사용하고, `mock`, `frontend-only`, `repo assignment` 같은 구현 설명은 사용자-facing 주요 문구에서 피한다.
- 리더보드는 활동 스냅샷이며 공식 평가, 마일리지, FORCE 점수로 보이게 쓰지 않는다.

## Mock Boundary

현재 시연은 브라우저 상태와 정적 fixture로만 동작한다. 실제 OAuth, GitHub App 호출, 파일 업로드, 개인정보 저장, Vercel production 운영, FORCE/마일리지 산정은 구현 범위가 아니다.

## Fixture Size Rule

`src/demo-fixtures.ts`는 12개 대회, 30명 학생, 12개 팀, 18개 저장소, 120개 활동 이벤트를 생성하지만 일반 소스와 같은 250 pure LOC 기준 안에 유지한다. 화면 컴포넌트, 라우팅, seed 데이터는 각각 작은 단위로 나누어 관리한다.
