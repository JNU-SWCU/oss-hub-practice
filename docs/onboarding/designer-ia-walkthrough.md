# 디자이너 화면 흐름 실습

이 실습은 Notion의 [화면 구조(Information Architecture)](https://app.notion.com/p/39c583e4660d81249bd3e2589953d03a) 전체 중 학생 온보딩과 역할별 핵심 화면을 뽑은 **실습용 부분 집합**을 Vite 시연 화면에서 직접 확인하는 과정입니다. 운영 제품의 전체 화면 목록이나 최종 라우팅 계약이 아니라, 처음 웹을 만드는 디자이너가 수정 결과를 빠르게 확인하기 위한 범위입니다.

## 1. 학생 첫 참여 설정 따라가기

로컬 서버를 실행합니다.

```bash
pnpm install --frozen-lockfile
pnpm dev
```

브라우저에서 아래 순서를 따라갑니다.

| 순서 | 주소 | 화면에서 확인할 것 | 다음 행동 |
| --- | --- | --- | --- |
| 1 | `/login` | GitHub 진입과 역할별 시연 진입이 구분되는가 | `학생` 선택 |
| 2 | `/student/setup` | 역할, 기본 정보, GitHub 기록 사용, 정보 이용 동의, 다음 화면 선택을 단계별로 확인하는가 | `진행 중인 활동` 또는 `새 프로그램` 선택 |
| 3 | `/student/dashboard` | 여러 팀/활동을 먼저 고르고, 선택한 팀의 GitHub 저장소와 제출 상태를 이어서 관리할 수 있는가 | `새 프로그램 보기` 또는 활동 카드 선택 |
| 4 | `/competitions` | 새로 신청할 프로그램을 검색·필터·정렬로 찾을 수 있고, 기존 활동 관리는 대시보드로 돌아가도록 안내하는가 | 프로그램 카드의 `상세/신청` |
| 5 | `/competitions/:id` | 일정·마일스톤·신청 행동이 상세 틀 안에 모여 있고, 기존 활동은 대시보드에서 관리한다고 설명하는가 | `이 프로그램 신청하기` |
| 6 | `/competitions/:id/apply` | 팀원 초대와 GitHub 저장소 연결 준비가 프로젝트 공간 만들기 흐름으로 보이는가 | 프로젝트 공간 만들기 |
| 7 | `/student/dashboard` | 새 신청 결과가 내 활동 목록과 신청 이력에 표시되는가 | 결과 확인 |

`학생 시작 흐름` 진행 표시는 첫 참여 설정 안에서만 사용합니다. 설정을 마친 뒤에는 대시보드, 프로그램 목록, 상세 화면에서 같은 단계표를 반복하지 않고 각 화면의 목적에 맞는 CTA로 이동을 안내합니다.

## 2. 화면 유형 표시하기

와이어프레임에는 화면 이름 옆에 유형을 적습니다.

- 페이지: 목록, 상세, 대시보드처럼 주소를 갖고 정보를 보여주는 목적지
- 모달: 신청, 제출, 편집처럼 현재 맥락 안에서 입력에 집중하는 작업
- 패널: 상세 화면 안의 마일스톤 현황처럼 관련 정보를 묶는 구역

시연 앱의 신청서는 현재 독립 주소를 가진 페이지입니다. 실제 제품 설계에서는 Notion IA에 맞춰 상세 화면 위의 모달로 전환할 후보이며, 주소 공유와 뒤로 가기 동작을 함께 정의해야 합니다.

## 3. 재사용 컴포넌트 점검

| 컴포넌트 | 재사용 화면 | 확인할 상태 |
| --- | --- | --- |
| 상단 길잡이 | 로그인 뒤 모든 화면(서비스 안내 포함) | 역할별 메뉴, 홈 이동, 역할 바꾸기 |
| 첫 참여 설정 Stepper | `/student/setup` | 역할, 기본 정보, GitHub 연결, 정보 이용 동의, 다음 화면 선택 |
| 내 활동 목록 | 학생 대시보드 | 여러 팀 선택, 저장소, 팀원, 제출 상태 |
| 프로그램 카드 | 프로그램 목록, 공개 아카이브 | 접수 중, 예정, 종료 |
| 상세 페이지 | 학생 프로그램 상세, 교직원 운영 상세 | 역할별 데이터와 행동 |
| 상태 배지 | 카드, 신청 이력, 저장소 | 색과 함께 한국어 상태 텍스트 |

같은 모양과 상호작용이 두 화면 이상에서 반복되면 기존 컴포넌트의 변형으로 해결할 수 있는지 먼저 확인합니다.

## 4. 상태와 반응형 검토

다음 크기에서 학생 흐름 전체를 확인합니다.

- 375px: 첫 참여 설정과 대시보드가 한 열로 쌓이고, 대시보드 첫 화면에서 `내 활동 목록 바로가기`로 긴 상태 카드 묶음을 건너뛸 수 있는가
- 768px: 한국어 제목과 버튼이 잘리거나 겹치지 않는가
- 1280px: 상단 길잡이와 콘텐츠의 시선 흐름이 안정적인가

데이터 화면에는 성공 화면만 그리지 않습니다. 로딩, 빈 상태와 다음 행동, 오류와 다시 시도, 성공 알림을 함께 설계합니다. 상태는 색만으로 전달하지 않고 `접수 완료`, `보완 요청`, `저장소 배정 완료`처럼 텍스트를 붙입니다.

## 5. 결과 기록

실습을 마치면 아래 세 가지를 남깁니다.

1. 흐름에서 막힌 지점과 이유
2. 재사용할 컴포넌트와 새로 필요한 상태
3. 데스크톱·모바일 캡처와 다음 검증 질문

자동 확인은 다음 명령으로 실행합니다.

```bash
pnpm typecheck
pnpm exec playwright test tests/e2e/demo.spec.ts
```
