# 디자이너 화면 흐름 실습

이 실습은 Notion의 [화면 구조(Information Architecture)](https://app.notion.com/p/39c583e4660d81249bd3e2589953d03a)를 Vite 시연 화면에서 직접 확인하는 과정입니다. 먼저 화면의 목적과 이동 순서를 확인하고, 그다음 시각 표현을 검토합니다.

## 1. 학생 시작 흐름 따라가기

로컬 서버를 실행합니다.

```bash
pnpm install --frozen-lockfile
pnpm dev
```

브라우저에서 아래 순서를 따라갑니다.

| 순서 | 주소 | 화면에서 확인할 것 | 다음 행동 |
| --- | --- | --- | --- |
| 1 | `/login` | GitHub 진입과 역할별 시연 진입이 구분되는가 | `학생` 선택 |
| 2 | `/consent` | 수집 정보와 공개 범위를 한국어로 이해할 수 있는가 | 필수 동의 후 계속 |
| 3 | `/student/dashboard` | 현재 신청·저장소 상태와 다음 행동이 한 화면에 보이는가 | `참여할 프로그램 둘러보기` |
| 4 | `/competitions` | 검색·필터·정렬과 프로그램 상태가 함께 보이는가 | 프로그램 카드의 `상세/신청` |
| 5 | `/competitions/:id` | 일정·마일스톤·신청 행동이 상세 틀 안에 모여 있는가 | `신청서 작성` |
| 6 | `/competitions/:id/apply` | 입력 작업이 별도 집중 화면으로 구분되는가 | 신청서 제출 |
| 7 | `/student/dashboard` | 신청 결과와 저장소 배정 상태가 텍스트로 표시되는가 | 결과 확인 |

각 화면 상단의 `학생 시작 흐름`은 같은 컴포넌트입니다. 화면마다 새 진행 표시를 만들지 않고 현재 단계만 바꿉니다.

## 2. 화면 유형 표시하기

와이어프레임에는 화면 이름 옆에 유형을 적습니다.

- 페이지: 목록, 상세, 대시보드처럼 주소를 갖고 정보를 보여주는 목적지
- 모달: 신청, 제출, 편집처럼 현재 맥락 안에서 입력에 집중하는 작업
- 패널: 상세 화면 안의 마일스톤 현황처럼 관련 정보를 묶는 구역

시연 앱의 신청서는 현재 독립 주소를 가진 페이지입니다. 실제 제품 설계에서는 Notion IA에 맞춰 상세 화면 위의 모달로 전환할 후보이며, 주소 공유와 뒤로 가기 동작을 함께 정의해야 합니다.

## 3. 재사용 컴포넌트 점검

| 컴포넌트 | 재사용 화면 | 확인할 상태 |
| --- | --- | --- |
| 상단 길잡이 | 로그인 뒤 모든 화면 | 역할별 메뉴, 홈 이동, 역할 바꾸기 |
| 학생 시작 흐름 | 동의, 대시보드, 목록, 상세, 신청 | 완료, 현재, 다음 단계 |
| 프로그램 카드 | 프로그램 목록, 공개 아카이브 | 접수 중, 예정, 종료 |
| 상세 페이지 | 학생 프로그램 상세, 교직원 운영 상세 | 역할별 데이터와 행동 |
| 상태 배지 | 카드, 신청 이력, 저장소 | 색과 함께 한국어 상태 텍스트 |

같은 모양과 상호작용이 두 화면 이상에서 반복되면 기존 컴포넌트의 변형으로 해결할 수 있는지 먼저 확인합니다.

## 4. 상태와 반응형 검토

다음 크기에서 학생 흐름 전체를 확인합니다.

- 375px: 진행 표시가 현재 단계 하나로 접히고, 폼과 동의 패널이 한 열로 쌓이는가
- 768px: 한국어 제목과 버튼이 잘리거나 겹치지 않는가
- 1280px: 상단 길잡이와 콘텐츠의 시선 흐름이 안정적인가

데이터 화면에는 성공 화면만 그리지 않습니다. 로딩, 빈 상태와 다음 행동, 오류와 다시 시도, 성공 알림을 함께 설계합니다. 상태는 색만으로 전달하지 않고 `접수 완료`, `보완 요청`, `저장소 배정 완료`처럼 텍스트를 붙입니다.

## 5. 결과 기록

실습을 마치면 아래 세 가지를 남깁니다.

1. 흐름에서 막힌 지점과 이유
2. 재사용할 컴포넌트와 새로 필요한 상태
3. 데스크톱·모바일 캡처와 다음 검증 질문

자동 확인은 다음 명령으로 실행합니다.

```bash
pnpm typecheck
pnpm exec playwright test tests/e2e/demo.spec.ts
```
