# Designer Quest

## Quest 1: 도메인 언어

- [ ] PRD에서 명사, 사용자, 상태, 행동, 결과를 추출한다.
- [ ] 모르는 용어를 `term / meaning / example / open question` 표로 정리한다.
- [ ] 용어가 화면 이름인지, 사용자 행동인지, 데이터 상태인지 구분한다.

핵심 용어: information architecture, navigation, user journey, user flow,
wireframe, mockup, prototype, affordance, hierarchy, responsive layout,
empty state, loading state, error state, accessibility, design token.

## Quest 2: 흐름과 화면

- [ ] Navigation bar의 각 항목에서 목적지와 진입 조건을 적는다.
- [ ] 정상 흐름과 취소, 뒤로가기, 권한 없음, 데이터 없음 흐름을 그린다.
- [ ] wireframe으로 구조를 먼저 검증하고 mockup으로 시각 스타일을 검증한다.
- [ ] 실제 사용자 목표가 완료되는 지점을 user journey에 표시한다.

## Quest 3: 재사용성

- [ ] 같은 의미와 상호작용을 가진 UI를 식별한다.
- [ ] Button, Input, Dialog, Table, Card, Navigation, Status, EmptyState의
  공통 상태를 기록한다.
- [ ] 도메인 용어와 동작이 들어간 컴포넌트는 feature 소유로 남긴다.
- [ ] 세 번 이상 반복되거나 변경 이유가 같은 것만 shared UI 후보로 올린다.

## Agent prompt checklist

- [ ] PRD 섹션과 대상 사용자 명시
- [ ] 원하는 산출물과 제외 범위 명시
- [ ] 화면/상태/반응형/접근성 검증 기준 명시
- [ ] 결과를 문서 또는 Figma 링크로 남김
